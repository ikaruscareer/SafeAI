# Manifest Examples (Contract v1)

## Minimal valid manifest

```json
{
  "schema_version": "1.2",
  "manifest_type": "safeai.kya",
  "contract": {
    "name": "safeai-manifest",
    "version": "1.0.0",
    "compatibility": {"minimum_reader_version": "1.0.0"}
  },
  "safeai": {"version": "2.2.0"},
  "project": {"project_id": "local-my-agent"},
  "agents": [],
  "findings": [],
  "summary": {"policy_decision": {"outcome": "pass", "reasons": ["No findings."]}},
  "assurance_boundary": {"statically_verified": ["declared tools"], "not_statically_verifiable": ["deployed IAM"]},
  "limitations": ["SafeAI results are static analysis evidence."]
}
```

```bash
safeai manifest validate minimal.json
# valid: minimal.json (contract safeai-manifest v1, schema_version 1.2)
```

## Representative scan manifest

Generate one from the bundled fixture (offline, deterministic):

```bash
safeai scan tests/fixtures/crewai/representative --manifest /tmp/safeai-manifest.json --no-registry
safeai manifest validate /tmp/safeai-manifest.json
safeai manifest verify /tmp/safeai-manifest.json
```

The representative manifest contains: `agents[]` with stable `agent_id`,
`framework`, `source_locations`; `tool_surface[]` keyed by
`(tool_identity, capability, access_mode)`; `components[]` with
`content_hash`; `dependency_inventory[]` (names only); `findings[]` with
`rule_id`, `fingerprint`, `severity`, `confidence`, `remediation`,
`provenance`, and `location`; `summary.policy_decision`
(`pass`/`warn`/`review-required`/`block`/`accepted-exception` with
rationale); and the `assurance_boundary` stating what was statically
verified vs. what cannot be verified.

## Integrity block

Manifests generated by this version carry:

```json
{
  "integrity": {
    "algorithm": "sha256",
    "canonicalization": "safeai-manifest-v1",
    "payload_sha256": "<64 lowercase hex>",
    "verified": false
  }
}
```

Canonicalization `safeai-manifest-v1`: UTF-8 JSON, sorted keys, compact
separators `(",", ":")`, over the whole document **minus** the `integrity`
block and **minus** volatile fields (`generated_at`, `scan.scan_id`,
`scan.started_at`, `scan.completed_at`). `verified` is always `false` at
generation time — it reflects a local verification action, never a proof
claim. `verify` recomputes and compares; see Workstream 2 docs in this
directory's README.
