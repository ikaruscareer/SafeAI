# Offline Manifest Integrity (Contract v1)

## What it is

Every manifest and portable inventory generated by this version carries:

```json
{
  "integrity": {
    "algorithm": "sha256",
    "canonicalization": "safeai-manifest-v1",
    "payload_sha256": "<64 lowercase hex>",
    "verified": false
  }
}
```

`verify` recomputes the digest locally and compares. This detects
**post-generation edits**. It does not prove source authenticity,
developer identity, scan truthfulness, runtime state, or deployment
attestation. `verified` is always `false` at generation; it may only
reflect a local verification action.

## Canonicalization `safeai-manifest-v1` (exact)

1. Deep-copy the document.
2. Remove the `integrity` block.
3. Remove volatile fields: top-level `generated_at`; `scan.scan_id`,
   `scan.started_at`, `scan.completed_at`.
4. Serialize: UTF-8 JSON, `sort_keys=True`, separators `(",", ":")`.
5. Digest: SHA-256 over those bytes, lowercase hex.

(Reference implementation: `safeai/kya/integrity.py:canonical_payload`,
`payload_digest`. Standard library only — `hashlib`, `json`.)

## Verify

```bash
safeai manifest verify safeai-manifest.json
# verified: safeai-manifest.json (sha256:<digest>)      → exit 0
# mismatch: ... (content changed after generation ...)  → exit 1
# no-integrity: ... (generated before integrity ...)    → exit 1
# unsupported-canonicalization / unsupported-version / malformed-block → exit 1
# error: unable to read ...                             → exit 1
```

Failure detail never contains document values — only the status and a
fixed explanation — so verification output cannot leak redacted content.
A mismatch cannot name which section changed (only the whole-payload
digest is stored); re-generate and diff to investigate.

Strict import mode (default off, backward compatible):

```bash
safeai registry import inventory.json --require-integrity
```

## Detached signatures (external — GPG)

SafeAI implements **hash integrity only** and will not ship a custom
signature system. For authenticity (who produced this manifest), sign the
file with your existing key infrastructure as a CI/release step:

```bash
# Detached ASCII-armored signature (recommended envelope):
gpg --armor --detach-sign safeai-manifest.json
# produces safeai-manifest.json.asc alongside the manifest + manifest.sha256:
sha256sum safeai-manifest.json > safeai-manifest.json.sha256
```

Consumers verify with their own keyring (`gpg --verify
safeai-manifest.json.asc safeai-manifest.json`), then run
`safeai manifest verify` for content integrity. Keep the two claims
separate: the GPG signature says *who signed this file*; the digest says
*the file was not edited since generation*; neither says the scan was
truthful or the deployment is safe.
